# Совместимость и миграция

## Действующие установки

Для V1/V2 с рабочим диском применяется пересборка из существующего Flake. Формат корня, домашний каталог, пароль, состояние DMS и локальные дисковые параметры сохраняются. В V2 завершён переход от Default, Gaming и Minimal к одной конфигурации хоста. В V3 установочные параметры создаются только для установки через `install.sh`. [Управление конфигурацией](docs/CONFIGURATION.md)

Для QEMU/KVM тестовый образ по-прежнему доступен через `nix build .#vm`. Только этот образ использует тестовый пароль. Установка в обычный диск QEMU задаёт пароль в диалоге.

## История проверок

Для V1 подтверждены запуск QEMU/KVM и чистая установка NixOS 26.05 Minimal в VMware. Проверены Niri, DMS, Ly, Kitty, Fish, оформление, PATH Vicinae и обновление через `nixos-rebuild`.

Для V2 на одном QEMU-хосте граф derivations сократился с 11 736 до 7 119 при неизменном `flake.lock`. Значения описывают граф сборки. Размер реализованных замыканий и расход диска не измерялись.

V2 также загружена владельцем на MacBookAir9,1 с ядром 6.18.55 и `t2bce`. Результаты работы периферии, ограничений Broadcom и сна перечислены в [профиле MacBook](docs/MACBOOK-T2.md).

V3 установлена владельцем в VMware из NixOS Minimal ISO с UEFI и виртуальным диском 30 ГиБ. Получены NixOS 26.11 и ядро 6.18.64. Подтверждены сеанс Niri + DMS, Ly, Kitty, Fish, Python 3.14.10, сеть, русская раскладка, пароль и `sudo`. Установка завершилась после ручных исправлений и отложения VS Code. V3.1 переносит исправления в установщик. Готовое ядро и модули T2 скачаны и проверены Nix. [Сценарий проверки в VMware](docs/VMWARE.md) · [Объекты кеша](docs/BINARY-CACHE.md)

Для работающего MacBook с V2 и ядром 6.18.55 подготовлена процедура перехода к V3.1 с отдельным checkout, проверкой прежних файловых систем, сборкой до переключения и сохранением загрузки рабочего поколения. [Обновление MacBook](docs/MACBOOK-UPGRADE.md)

Владелец подтвердил загрузку V3.1 на MacBookAir9,1 с 6.18.35 и `apple-bce`, ручной сон и пробуждение после открытия крышки. V3.2 переносит проверенный режим сна в профиль `macbook`. При обновлении уже установленной системы используйте `nixos-rebuild build` с прежней локальной аппаратной конфигурацией. Перед `boot` проверьте, что `/boot` остаётся на Linux ESP. Уберите временные переопределения сна, если они использовались для теста V3.1. [Параметры V3.2](docs/MACBOOK-T2.md)
