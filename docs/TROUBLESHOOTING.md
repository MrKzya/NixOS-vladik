# Диагностика

| Симптом | Проверка |
| --- | --- |
| Live ISO запущен в Legacy BIOS | Наличие `/sys/firmware/efi`, настройка UEFI гостя |
| Корень или ESP отсутствует в меню | GPT, Btrfs/Ext4, FAT32 и GPT-тип ESP, вывод `lsblk -f` |
| Несовпадение раздела или точки монтирования | `lsblk -o NAME,TYPE,FSTYPE,PARTUUID,MOUNTPOINTS`, `findmnt -R /mnt`. При занятом разделе установщик останавливается |
| Сетевой линк, IP или маршрут отсутствуют | Отдельная диагностика через `ip -br link`, `ip -br addr`, `ip -4 route` и `ip -6 route` |
| DNS не отвечает | Повторная проверка в меню DNS, `getent ahosts github.com` |
| Ошибка TLS или HTTP | TLS — системное время и сертификаты. HTTP — ответ конкретного источника. Тайм-аут — доступность по IPv4/IPv6, прокси и маршрут |
| Загрузка VS Code или другого пакета остановилась | Строки `Current` и `Last activity` показывают операцию и время без событий. После автоматических повторов выберите Retry, Change components или Defer component |
| Готовый T2-объект недоступен | Точный путь в журнале и текущий статус Cachix. [Проверка кеша](BINARY-CACHE.md) |
| Не подтверждён GRUB | Журнал и `/mnt/boot/EFI/BOOT/BOOTX64.EFI` в подтверждённом Linux ESP |
| Сбой после первой загрузки | Предыдущее рабочее поколение GRUB или Live ISO, если поколение первое |

При рабочем системном DNS Live-среда сохраняет настройки. При сбое временный DNS назначается маршрутизируемому интерфейсу через systemd-resolved. Без него используется временный `resolv.conf` в отдельном mount namespace. Изменения снимаются при обычном выходе и обработанных сигналах. При `SIGKILL` или сбое Live сеанс systemd-resolved может потребовать переподключения сети. Явный выбор DNS записывается в настройках NetworkManager установленной системы.

Журнал находится в закрытом каталоге `/run/nixos-vladik.*/install.log` и после успешной установки сохраняется в `/var/log/nixos-vladik-install.log`. В журнале могут присутствовать локальные имена устройств и UUID. Перед публикацией диагностического фрагмента они удаляются. При аварийной остановке повторяется тот же этап или весь запуск с тем же проверенным профилем и носителями. [Правила повтора](INSTALLATION.md#повтор-и-результаты)

Установщик проверяет конкретные URL из `flake.lock`, `cache.nixos.org` и Cachix для T2. Проверка показывает маршруты IPv4/IPv6, имена DNS, адрес текущего источника и номер попытки. При сбое IPv6 используется доступный IPv4. По умолчанию DNS получает 15 секунд на запрос, HTTPS 25 секунд на подключение и 50 секунд на запрос с тремя попытками. Порог простоя при загрузке пакетов составляет 90 секунд. Например, для медленной сети

```bash
sudo env NIXOS_VLADIK_DNS_TIMEOUT=25 NIXOS_VLADIK_CONNECT_TIMEOUT=40 \
  NIXOS_VLADIK_HTTPS_TIMEOUT=90 NIXOS_VLADIK_HTTPS_ATTEMPTS=3 \
  NIXOS_VLADIK_DOWNLOAD_IDLE_TIMEOUT=120 bash install.sh
```

Полный журнал можно наблюдать через `sudo tail -f` по пути, который установщик печатает в начале. События `@nix` в файле содержат исходные счётчики и сообщения. Процент в терминале оценивает только объявленные Nix операции. Счётчик байт суммирует наблюдаемые загрузки и может учитывать трафик повторной попытки.

## Karing и TG WS Proxy

Karing 1.2.26.2934 запускается из меню или через `karing`. Wrapper задаёт каталог библиотек Flutter, схемы GSettings для System Proxy и имя старой KDE-утилиты через `kwriteconfig6`. Режим **System Proxy** можно проверять отдельно с выключенным **TUN Mode**.

TUN в этой версии зависит от закрытого `vpn_service`, который ожидает root-владельца и setuid/setgid на `karingService` и предлагает переписать их через `sudo`. Upstream подтвердил, что вариант с одними capabilities сейчас не поддерживает. Для штатного TUN в NixOS нужен поддерживаемый интерфейс, через который клиент сможет использовать ограниченный системный сервис. [Механизм авторизации и ответ upstream](https://github.com/KaringX/karing/issues/1844)

`tg-ws-proxy` запускает трей из исходников 1.12.0 с GTK, GLib и Ayatana из закреплённого Nixpkgs. `tg-ws-proxy-cli --help` показывает параметры отдельного CLI. `tg-ws-proxy --smoke-test` открывает и закрывает тестовое окно и создаёт индикатор без запуска прокси. Обновления обоих пакетов применяются через пересборку NixOS.
